SentinelDesk

Un sistema operativo colaborativo para personas y agentes de IA. Un escritorio Linux, en un contenedor, que manejan los dos — viendo la misma pantalla, turnándose, y leyendo los errores del otro.

Esa segunda mitad no es una metáfora de una API. Es el mismo display X, la misma sesión, la misma sala:

  • El agente es un participante, no un proceso en segundo plano. Tiene un nombre en la lista y un puntero en pantalla con su propio color, para que nunca sea ambiguo si el mouse lo movió un colega o el modelo.
  • Se turnan. El control se reclama, nunca se asume — por cualquiera, agente incluido, haya o no alguien mirando. Nadie tiene los controles hasta que los pide, así que entrar para mirar no te deja encima un escritorio que no querías. Cuando alguien está manejando, pedirlo le pone un cartel en su pantalla y no contestar es que no.
  • Leen el mismo estado. Todo comando ejecutado en una terminal informa su código de salida, lo haya corrido quien lo haya corrido, así que una persona puede toparse con un error y pedirle al agente que mire lo que pasó de verdad.
  • Una captura, muchos observadores. El escritorio se codifica una sola vez y se reparte: a cada navegador, a la grabación, a una transmisión en vivo. Un participante más cuesta ancho de banda, no CPU.

Las personas lo manejan desde una capa de control en el navegador. El agente lo maneja por un socket local con 134 herramientas MCP. Ninguno es invitado del otro.

¿Recién llegás?

Leé Instalarlo y La capa de control. Lo demás es referencia para volver cuando haga falta.

Sobre qué está construido

Un solo binario Go. GStreamer corre adentro del proceso vía go-gst y no como un hijo de él, así que el codificador queda accesible en caliente — el bitrate sigue a la red, los fotogramas clave responden a un pedido, y un destino externo se engancha sin frenar nada.

Instalarlo y ponerlo a andar

Todo corre en un contenedor. En las máquinas que se conectan no hay nada que instalar — el cliente es el navegador.

Qué hace falta

  • Docker con Compose v2. Docker Desktop en macOS y Windows, Docker Engine en Linux.
  • 2 GB de RAM y dos núcleos para un 1080p30 cómodo. La GPU es opcional y cambia mucho — mirá Aceleración por hardware.
  • amd64 para Steam y Wine, que están solamente en la imagen full. Todo lo demás corre también en arm64, en las dos imágenes.

Formas de arrancarlo

La forma de un solo comando, en un VPS, una Raspberry Pi o cualquier host Linux. Instala Docker si falta, baja la imagen publicada de Docker Hub y deja el escritorio corriendo en segundo plano — nada que clonar, nada que compilar.

curl -fsSL https://raw.githubusercontent.com/sentineldesk/desktop/main/install.sh | sudo bash

Agregá --full para la imagen más pesada, --pass <p> para fijar la contraseña y --ip <addr> en un VPS público para que el video sea alcanzable. --help lista todas las opciones.

Las imágenes publicadas, dos servicios, un comando. Descargá el archivo y levantalo — sin clonar, sin compilar:

curl -fsSLO https://raw.githubusercontent.com/sentineldesk/desktop/main/docker-compose.yml
AUTH_PASS=cambiame HOST_IP=192.168.0.100 docker compose up -d

HOST_IP es la dirección por la que los navegadores llegan a esta máquina — su IP de la LAN, o la pública en un VPS. Fuera de localhost es obligatoria y no opcional: si no, WebRTC anuncia la IP del bridge del contenedor, que nada de afuera alcanza, y la página se queda en «Estableciendo WebRTC» con el video en negro. Después abrí https://192.168.0.100:8080.

Poné SENTINELDESK_TAG=full para la imagen pesada.

Qué levanta

serviciocontenedorqué es
sentineldesksentineldesk el escritorio: X, el navegador, las apps, el stream WebRTC, el servidor MCP
agentsentineldesk-agent el runtime que lo maneja — el cerebro detrás del panel de chat

El agente es opcional, y nombrar al escritorio es cómo se dice eso:

docker compose up -d                # el escritorio y un agente al lado
docker compose up -d sentineldesk   # el escritorio solo

El escritorio no tiene depends_on ni ningún vínculo con el agente, así que la segunda línea es un despliegue completo y no uno mutilado. El orden tampoco importa: si arranca primero, el agente espera al escritorio y se reconecta cuando vuelve.

Cómo se unen los dos

Un volumen, sentineldesk-run, con sockets Unix y montado en ambos. Ese es el único vínculo entre ellos. El agente no tiene puertos ni red propia, así que nada de la conversación sale de esta máquina — y el agente solo puede hacer lo que ese socket concede, que es por qué acá hay un borde de seguridad y no dos.

sentineldesk-auditel registro de acciones — aparte, para que borrar un perfil nunca se lleve el registro
sentineldesk-agentel modelo elegido, las claves y el historial del agente

Comandos de todos los días

docker compose ps                      # qué está arriba
docker compose logs -f sentineldesk    # seguir el escritorio
docker compose logs -f agent           # seguir el agente
docker compose restart agent           # reiniciar un servicio
docker compose down                    # parar ambos, conservar los volúmenes
docker compose pull && docker compose up -d    # actualizar en el lugar

down no toca los volúmenes, así que el home, el registro y las claves del agente sobreviven. Para empezar realmente de cero, borralos por nombre — y leelo como el comando destructivo que es: docker volume rm sentineldesk-home sentineldesk-agent.

Configurarlo

Compose lee un .env al lado del archivo, que es el lugar más prolijo para lo que si no repetirías en la línea de comandos:

AUTH_USER=admin
AUTH_PASS=una-clave-de-verdad
HOST_IP=192.168.0.100
SENTINELDESK_TAG=latest        # o `full`
TZ=America/Argentina/Buenos_Aires
KEYBOARD_LAYOUT=latam
HTTP_PORT=8080

Todas tienen un valor por defecto; solo AUTH_PASS y HOST_IP conviene fijarlas antes de que alguien más pueda llegar al despliegue.

HTTPS viene por defecto

El escritorio sirve TLS de fábrica: sin configurar nada genera un certificado autofirmado una vez, lo guarda en el volumen del home, y el navegador te pide aceptarlo exactamente una vez. Tu propio certificado gana con TLS_CERT/TLS_KEY. Es más que el candadito: los navegadores solo permiten el micrófono y el portapapeles rico en orígenes seguros, así que un escritorio por HTTP plano perdía funciones en silencio.

Para terminar TLS vos mismo con un proxy adelante — nginx, Caddy, Nginx Proxy Manager — poné TLS_SELFSIGNED=0 para que el backend hable HTTP plano con el proxy.

Un relay para redes hostiles

El peer-to-peer falla en NAT simétrica y donde se descarta UDP. Hay un servicio TURN en el archivo, apagado por defecto, porque un relay lleva cada cuadro de cada sesión por adentro y pagar eso cuando nadie lo necesita es el intercambio equivocado:

docker compose --profile turn up -d

Poné CLIENT_TURN_URLS en el escritorio cuando esté corriendo, o a los navegadores nunca se les dice que el relay existe.

La VPN incorporada

El escritorio puede discar OpenVPN, que necesita un dispositivo túnel y la capacidad de configurar rutas. Los dos están comentados en el compose — descomentá cap_add: NET_ADMIN y devices: /dev/net/tun en el servicio sentineldesk. NET_ADMIN deja al contenedor manejar su propia pila de red, que es un permiso real, así que dejalo apagado en un despliegue que nunca vaya a discar una.

Para tocar el código — el camino de quien contribuye. La imagen se construye desde la raíz del repositorio para que el Dockerfile llegue tanto a las fuentes Go como a los assets del escritorio.

# chequeo rápido de tipos en el host, sin contenedor
go build ./...
# construir las dos variantes
make image
# o solo una de ellas
make image-lite
make image-full
# o, sin make — ojo con el --target
docker build -f deploy/Dockerfile --target desktop -t sentineldesk:latest .

--target desktop no es opcional. La última etapa del Dockerfile es full, así que omitirlo construye LibreOffice, Firefox, GIMP, Wireshark y todo lo demás — unos 2,5 GB — y después le pone la etiqueta sentineldesk:latest, un nombre que en todos los demás lugares significa lite.

La interfaz web va embebida con go:embed, así que tocar cualquier cosa dentro de internal/webui/assets/ obliga a reconstruir la imagen — el cambio no aparece recargando la página.

La primera vez

Abrí https://localhost:8080 (autofirmado — aceptá la advertencia del navegador una vez). Con AUTH_USER y AUTH_PASS definidos pide usuario y contraseña; sin ellos queda abierto.

# seguir los logs del escritorio
docker logs -f sentineldesk
# una shell de root adentro del contenedor
docker exec -it -u root sentineldesk bash
# pararlo y eliminarlo (el volumen del home se conserva)
docker rm -f sentineldesk

Desde un checkout del código, los mismos tres son make logs, make shell y make down.

El escritorio guarda su home en un volumen con nombre, sentineldesk-home, así que los perfiles del navegador, las aplicaciones instaladas y la biblioteca de Steam sobreviven a un reinicio o a una recompilación.

La resolución no la cambia el binario

DISPLAY_WIDTH y DISPLAY_HEIGHT las lee Xvfb al arrancar, no el servidor. Por eso el escritorio se puede achicar en caliente pero nunca agrandar más allá de lo reservado al inicio — y por eso cambiarlas implica reiniciar el contenedor.

Flags de línea de comandos

El binario toma nueve. Cinco son del lado de la IA; las otras cuatro hacen del binario su propia distribución. Todo lo demás es variable de entorno, porque todo lo demás es configuración de un servicio y no una decisión que se toma en cada invocación.

FlagDescripción

-mcp-stdioCorrer como puente stdio en vez de como escritorio: se conecta a -mcp-sock y retransmite JSON-RPC entre el stdin/stdout del host de IA y ese socket
-mcp-policy <nivel>full, safe o readonly — sólo para este puente

Las últimas tres restringen una conexión, encima de lo que MCP_POLICY ya permita. Un puente puede angostarse pero nunca ampliarse — y eso es lo que hace seguro darle a un agente un extremo de sólo lectura sin cambiarle nada a nadie más:

docker exec -i -u sentineldesk sentineldesk \
  /usr/local/bin/sentineldesk -mcp-stdio \
  -mcp-sock /run/user/1000/sentineldesk-mcp.sock \
  -mcp-policy safe -mcp-deny 'ssh_*,install_packages'

Aceleración por hardware

El codificador se elige al arrancar corriendo un pipeline de prueba real para cada candidato, así que lo que obtenés refleja lo que de verdad funciona en ese host y no lo que dicen los drivers. Forzá uno con ENCODER=nvenc|vaapi|h264|vp8.

Para usar una GPU, pasá el dispositivo al contenedor. Para VA-API agregá --device /dev/dri y la sonda la elige sola. NVENC necesita el NVIDIA Container Toolkit y --gpus all; sin una GPU utilizable el escritorio cae a codificación por software.

Por qué x264 y no VP8 sin GPU

Medido sobre contenido de escritorio, libx264 en veryfast sostiene 1080p por alrededor de un tercio de lo que necesita vp8enc, y H.264 es lo que todo navegador decodifica por hardware. Eso también importa del lado que recibe: un cliente que no da abasto se ve como una red congestionada ante el estimador, y arrastra el bitrate de toda la sala hacia abajo.

Producción

El modelo de seguridad

Es corto de enunciar: el WebSocket es la única puerta.

El primer mensaje del WebSocket tiene que ser uno de autenticación con usuario y contraseña, o con un token de sesión. Hasta que valide no hay handshake de WebRTC en absoluto — ni oferta SDP, ni ICE, ni DataChannel. Un token inválido, una oferta que intente saltear la autenticación, o silencio pasados los diez segundos, cierran la conexión.

Los fallos repetidos desde un mismo origen se limitan y después se bloquean un rato, así que una contraseña no es algo que se pueda adivinar rápido.

  • Definí AUTH_SECRET con un valor fijo. Sin definir es aleatorio, y cada reinicio invalida la sesión de todos.
  • FILES_ROOT limita hasta dónde llega el administrador de archivos. Dejalo adentro del home salvo que quieras otra cosa.
  • Las descargas viajan con un ticket de un solo uso en la URL en vez del token de sesión, así que un enlace que se filtre ya está gastado.
  • El socket MCP es 0600 y local al contenedor. Nunca se expone por la red.

TLS

El escritorio sirve HTTPS por sí mismo. Sin nada configurado genera un certificado autofirmado en el primer arranque y lo guarda en el volumen del home; TLS_HOSTS le pone los nombres correctos. Para usar el tuyo, pasá TLS_CERT y TLS_KEY (uno sin el otro se niega a arrancar). Para terminar TLS en un proxy inverso delante — nginx, Caddy — poné TLS_SELFSIGNED=0 para que el backend hable HTTP plano con el proxy. En cualquier caso el cliente pasa a wss:// solo. Esto importa más allá del candado: el micrófono y el portapapeles enriquecido solo funcionan en un origen seguro.

Si el host está detrás de NAT y no tiene su dirección alcanzable en su propia interfaz — un VPS en la nube, o Docker en una VM — poné NAT1TO1_IP con esa dirección (su IP de LAN o pública) para que WebRTC anuncie algo que el navegador pueda alcanzar. Sin eso el navegador recibe la dirección del bridge del contenedor y el video conecta y queda en negro.

TURN en macOS y Windows

Docker Desktop corre el contenedor adentro de una VM, así que las direcciones que ICE descubre son las de la VM y no son alcanzables, y puede no formarse una conexión directa. Un relay TURN cierra esa brecha — apuntá el navegador a uno con CLIENT_TURN_URLS (y TURN_USER / TURN_PASS). En un host Linux con los puertos de arriba publicados, nada de esto hace falta.

La capa de control

Todo lo que se opera vive en una barra a la izquierda de la ventana del navegador. Flota sobre el video en vivo de un escritorio real, así que es translúcida a propósito: lo que tapa es escritorio que dejás de ver.

Con º se muestra y se esconde. Esa tecla nunca llega al escritorio remoto.

Las ventanas de esta capa — el administrador de archivos, las estadísticas, la transmisión — siguen abiertas mientras usás la barra, se arrastran de su título y se cierran sólo con su propia ×. Doble clic en el título vuelve a centrar la que quedó en un lugar incómodo.

Compartir la sesión

Un escritorio, varios participantes. El modelo es el de una consola compartida: exactamente un participante tiene el control a la vez y el resto mira. La captura se codifica una sola vez y se manda a todos, así que un espectador más cuesta ancho de banda, no CPU.

Tomar y soltar el control

El panel de presencia arriba de la barra dice en cuál de los tres estados estás: estás manejando, lo está haciendo otro, o no lo tiene nadie. Entre personas el control es cooperativo — cualquiera puede tomarlo, y quien lo tenía ve el cambio al instante. No hay jerarquía, porque todos entraron con la misma credencial.

Entrar no te da el control. El escritorio arranca sin nadie manejando y sigue así hasta que alguien lo pida, así que abrirlo para mirar cómo trabaja un colega es algo que podés hacer sin sacarle la máquina de abajo. Tocá Tomar control cuando de verdad lo quieras.

Soltar deja los controles libres; no se los pasa al siguiente. «Terminé» y «te toca» son dos frases distintas, y sólo la primera es cierta alguna vez. Lo mismo vale si quien maneja cierra la pestaña: los controles quedan libres en vez de caerle encima al que lleva más tiempo conectado.

La barra flotante

Una barra abajo de la pantalla le dice a todos cómo está la cosa, y trae el botón: verde cuando los controles están libres, ámbar cuando maneja otro. Se queda mientras eso sea cierto en vez de pasar de largo — el momento en que el agente termina una tarea es justo cuando podés estar mirando para otro lado.

Quién es quién: tintas y punteros

Cada participante recibe un color al entrar — amarillo el primero, después cian, magenta y casi-negro — y el violeta siempre es el agente de IA, nunca una persona. Los puntos de la lista lo llevan, y el puntero también: mientras mirás, tu mouse sobre el escritorio se dibuja ahí para los demás, con tu nombre y en tu tinta, así que señalar cosas funciona sin tomar el control. Las grabaciones y los streams salientes incluyen esos punteros, porque se dibujan sobre el escritorio mismo.

El turno del agente de IA

El agente es un participante como cualquier otro: un nombre en la lista y un puntero en pantalla con su propio color, para que nunca sea ambiguo si el mouse lo movió un colega o el modelo.

La regla es una línea: el control se reclama, nunca se asume. Eso vale para el agente haya o no alguien mirando — una sala vacía era un pase libre y dejó de serlo. Pedirlo no le cuesta nada cuando los controles están libres, porque la respuesta vuelve al instante; lo que se gana es una sala que siempre sabe quién tiene el escritorio. Cuando alguien SÍ está manejando, el agente tiene que pedírselo — aparece un cartel en tu pantalla con un temporizador que se vacía, y no contestar es no.

Leer los errores del otro

Todo comando ejecutado en una terminal de este escritorio informa su código de salida, lo haya corrido quien lo haya corrido. Así una persona puede toparse con un error, pedirle al agente que lo mire, y el agente lee lo que pasó de verdad en vez de que se lo cuenten.

Hablar con el agente desde el navegador

El botón redondo arriba de la barra abre un chat al lado del escritorio: la pantalla se parte, el escritorio queda a la izquierda y la conversación a la derecha. Le pedís algo en castellano, el agente trabaja, y ves lo que hace mientras lo hace — cada herramienta que llama aparece bajo su respuesta, alineada con lo que se mueve en la pantalla de al lado.

El punto en el botón dice si hay con quién hablar antes de que lo aprietes: verde listo, ámbar corriendo pero sin modelo configurado, gris no está.

Hace falta el agente

El escritorio funciona solo; el agente es opcional y vive en su propio repositorio. El panel distingue tres situaciones y para cada una muestra el comando que la resuelve — no está instalado, está instalado y no está corriendo, o está corriendo sin modelo. Copiás la línea, la corrés, y el panel se pone verde solo: nada que recargar.

El escritorio nunca depende de él

Que el agente no esté, que se le venza la API key o que se le trabe el loop cuesta el panel de chat y nada más. El escritorio arranca igual, la sesión sigue, y reiniciar el agente no toca ni el video ni a quien esté mirando. Con AGENT_ENABLED=0 el plano entero queda apagado.

Trabaja en automático, pero el control se pide

Desde el chat el agente ejecuta sin preguntar por cada paso — para eso está. Lo que no cambia es la regla del escritorio: si vos tenés el control, te lo tiene que pedir, con el mismo cartel de siempre. Y si él decide consultarte algo antes de hacerlo, te lo pregunta en el chat, donde estás mirando.

El historial es el mismo

Las conversaciones del panel y las de la terminal son las mismas: se guardan en la misma base y el botón de historial lee esa. Una tarea que empezaste escribiendo en la terminal aparece en el navegador, y al revés.

Capturas y grabación

Las dos están en el grupo Captura, y las dos pasan por el servidor y no por el navegador. Eso significa que el archivo sale con la calidad del framebuffer, sin la compresión del streaming — y en MP4, que se abre en cualquier sistema operativo sin instalar nada. También hay WebM y MKV.

Los punteros de los demás participantes se dibujan sobre el propio display X, así que aparecen en las capturas y grabaciones igual que en pantalla.

Transmitir el escritorio hacia afuera

Transmitir, en el grupo Captura, manda la sesión en vivo a otro lado: YouTube, Twitch o Facebook con sólo la clave de transmisión, o una dirección completa para un VLC u OBS tuyo.

Reusa la codificación que la sala ya está produciendo. Salir en vivo no interrumpe lo que los demás están viendo, y un destino más cuesta un multiplexor y un socket en vez de una segunda captura de la pantalla. El multiplicador que sí es real es el ancho de banda: cada destino se lleva el stream completo fuera de la máquina.

Decide quien tiene el control, y la lista de destinos la ve toda la sala — que una sesión se esté transmitiendo no es algo para enterarse después. Las claves de transmisión se redactan antes de llegar a cualquier navegador o log.

YouTube, Twitch, Facebook

Elegí la plataforma y pegá sólo la clave de transmisión. La dirección de ingesta ya se conoce, así que no hay nada que ir a buscar.

Verlo en VLC

Dos pasos, en este orden: primero poné VLC a escuchar, y recién ahí apretá Salir en vivo. Si no hay nadie escuchando, el escritorio no tiene a dónde mandarlo.

Paso 1 — poner VLC en modo escucha en tu propia máquina:

VLC no deja un comando vlc; hay que llamar al binario que está adentro de la aplicación.

"/Applications/VLC.app/Contents/MacOS/VLC" \
  --network-caching=200 "udp://@:5000"
vlc --network-caching=200 "udp://@:5000"

Desde PowerShell o el símbolo del sistema:

"C:\Program Files\VideoLAN\VLC\vlc.exe" ^
  --network-caching=200 "udp://@:5000"

El @ es lo que hace que VLC escuche en vez de conectarse — sin eso no pasa nada y no imprime ningún error. --network-caching=200 le baja el búfer propio de un segundo a 200 ms; si lo dejás afuera vas a culpar a la transmisión por una demora que es de VLC.

Podés verificar que está escuchando de verdad:

# Linux / macOS — tiene que mostrar UDP *:5000, no un puerto alto al azar
lsof -nP -iUDP:5000

Paso 2 — en la barra, elegí VLC / OBS y poné la dirección:

Dónde corre DockerDirección a usar
Docker Desktop, misma máquina que VLC (macOS, Windows) udp://host.docker.internal:5000
Docker en Linux, misma máquina que VLC udp://172.17.0.1:5000
Otra máquina udp://<IP de esa máquina>:5000

Dejá Pueden entrar espectadores en cualquier momento sin marcar. Es un receptor tuyo — no necesita un fotograma clave cada dos segundos, y los bits que se ahorran vuelven a mantener el texto legible.

Por qué udp:// y no srt:// para VLC

VLC 3 habla SRT sólo como llamador: puede conectarse hacia afuera, pero no puede recibir una conexión, y el ?mode=listener lo ignora en silencio. Si apuntás SentinelDesk hacia él por SRT, los dos lados terminan llamando, ninguno atiende, y no se registra nada porque no falló nada. Para VLC usá udp://.

Verlo en OBS

Agregá un Origen de medios, destildá Archivo local, y poné el mismo udp://@:5000 en el campo de entrada. OBS también acepta srt://, en modo escucha.

Qué protocolo usar

EsquemaPara qué
udp://Un reproductor en tu red. Funciona en todos lados, no hay nada que negociar.
srt://Un receptor por internet que escucha: un servidor SRT, OBS en modo escucha. Se recupera de pérdida de paquetes; en una LAN no aporta nada.
rtmp://, rtmps://Las plataformas. Viejo e incómodo, y lo único que aceptan.

Sobre los fotogramas clave

Un espectador no ve nada hasta que llega un fotograma clave, así que una plataforma que atiende a gente que aparece en cualquier momento necesita uno cada dos segundos. Eso se aplica solo mientras haya un destino de esos conectado, y vuelve a ser bajo demanda apenas se detiene el último.

Los fotogramas clave son de diez a cincuenta veces más grandes que uno normal, y cada bit que ocupan es un bit que no se gastó en el texto de tu pantalla. Un receptor que arrancás vos puede simplemente esperar al primero, y por eso se ve más nítido.

Sólo H.264

Ningún destino de streaming acepta VP8. La detección automática del codificador prefiere x264 antes que VP8, así que normalmente ya se cumple; en un host donde no, poné ENCODER=x264.

La dirección se recuerda

Lo que escribís queda guardado en este navegador, por destino, así que reabrir el panel mientras transmite muestra lo que se está mandando y detener no significa volver a pegar la clave. Se guarda igual que una contraseña en el navegador: en esta máquina, para este sitio, y en ningún otro lado.

Mover archivos

Archivos, en el grupo Sesión, abre un administrador de dos paneles: el escritorio remoto a la izquierda, tu propia máquina a la derecha. Las teclas de función de abajo hacen lo de siempre — F5 copiar, F6 renombrar, F7 carpeta nueva, F8 borrar, F2 refrescar.

También podés soltar archivos en cualquier parte de la página para mandarlos al escritorio, sin abrir el administrador.

Las descargas viajan con un ticket de un solo uso en la URL en vez de tu token de sesión, así que un enlace que se filtre ya está gastado y no sirve. FILES_ROOT limita hasta dónde llega el administrador.

Tu micrófono, en el escritorio

Micrófono, en el grupo Captura, manda tu micrófono al contenedor, donde las aplicaciones lo ven como un dispositivo de entrada real — y no como el monitor de algo que está sonando, que es lo que los navegadores esconden de su selector de micrófonos. Cuál usa se elige en Ajustes — el engranaje del riel, o clic derecho sobre el botón.

Sólo el participante que tiene el control puede publicar audio. Tu voz pasa a ser parte del escritorio: las aplicaciones, las grabaciones y los streams salientes la escuchan. Para hablar con las demás personas de la sala sin que el escritorio oiga una palabra, mirá Voz.

Voz, entre quienes miran

Voz, en el grupo Sesión, es la otra conversación: una conferencia de voz entre las personas de la sala, navegador a navegador. El escritorio no la oye nunca — las grabaciones, los streams salientes y las aplicaciones de adentro no llevan rastro de ella. Imaginate cuatro personas relatando un video que suena en la pantalla compartida: el relato es Voz; el sonido del video sigue siendo del escritorio.

Se entra de a uno, como con un handy: apretar tu propio botón captura tu micrófono y te anuncia, y no le enciende nada a nadie más. Quien también tenga Voz activa se conecta con vos directo, par a par — el audio viaja entre navegadores, y el servidor sólo releva los sobres sellados del saludo sin leerlos. Con tres o cuatro personas es una malla: cada par tiene su propia conexión, todos se escuchan con todos.

En la conferencia a solas no suena nada: el contador del botón muestra cuántos pares hay conectados, y 0 es un estado de espera, no una falla. El orden tampoco importa — quien active Voz más tarde se anuncia y los pares se arman solos. Apretar el botón de nuevo sale de la conferencia y libera tu micrófono.

Qué dispositivo usa cada conversación — el micrófono del escritorio y el de la conferencia — se elige en Ajustes, donde un medidor de nivel y la prueba de escucharte responden "¿éste me oye?" antes de que nadie más tenga que hacerlo. Voz no necesita control ni turno: con mirar alcanza. Es la conversación sobre el escritorio, no con él.

Ajustes: tus dispositivos y tu nombre

El engranaje del grupo Sesión — o el clic derecho sobre Micrófono — abre Ajustes. Responde las dos preguntas que toda llamada termina haciendo: qué dispositivo, y si me escucha.

Micrófono y Voz se eligen por separado, porque son actos distintos — la entrada del propio escritorio y la conferencia de quienes miran — y alguien con vincha y micrófono de mesa realmente los quiere separados. El medidor de nivel sigue al último selector que tocaste; Escucharme reproduce tu propia voz en la salida elegida (mejor con auriculares), y la prueba de parlantes suena en la salida que elegiste. Las elecciones se recuerdan por navegador y rigen al instante, incluso a mitad de sesión.

Tu nombre también vive acá: letras, números, espacio, guion y guion bajo. Aparece en la lista, en el registro de auditoría de la sesión y en la etiqueta del puntero que ven los demás — ponelo una vez y la sala deja de llamarte «Viewer 2».

El teclado en pantalla

Teclado, en el grupo Visor, ancla un teclado completo al borde inferior de la pantalla — pensado para tablets, útil en cualquier lado. Dos distribuciones (ES, español ISO con ñ, ç y las teclas muertas; EN, US ANSI), pad numérico y bloque de navegación detrás del botón 123, y una variante compacta Mini. El botón — lo guarda en una pastilla abajo al centro; tocala para traerlo de vuelta.

Los acentos se componen como en el teclado de un celular: tocá ´ y después una vocal y llega una á — tocá el acento dos veces para el carácter literal. Shift, Ctrl, Alt y AltGr son trabas: tocá una, tocá una tecla, y viaja el acorde. La tecla del monitor es el ⊞ de este escritorio — un toque abre el menú de aplicaciones.

En una pantalla táctil el escritorio mismo es manipulación directa: un dedo es el puntero con el botón izquierdo apretado, dos dedos hacen scroll, y un toque rápido con dos dedos es el botón derecho.

Con el teclado abierto, un teclado físico ilumina sus propias teclas a medida que escribís — el mismo rojo de una pulsación táctil. Es un «así escribo» en vivo, y confirma de un vistazo que las teclas están llegando.

La IA del propio navegador puede manejarlo

Además del agente que se conecta por MCP, el escritorio ofrece un conjunto de herramientas a la IA que trae el propio navegador — la emergente API de «model context» que lee el Gemini integrado de Chrome. Nada que instalar ni clave que pegar: desde que estás autenticado y conectado, la página publica sus herramientas y el modelo del navegador puede actuar a través de ellas.

Las herramientas hacen exactamente lo que hacés vos, por exactamente tu camino: escribir, pulsar teclas, mover y hacer clic con el puntero, scroll, poner el portapapeles, tomar una captura, listar y organizar archivos, fijar la calidad, tomar o soltar el control. Viajan por el mismo DataChannel autenticado que tus propios clics — sin endpoint aparte, sin segundo login. Así la IA del navegador llega exactamente hasta donde llegás vos y ni un paso más: todo lo que escribe al escritorio espera a que se tenga el control, y le pide al modelo que lo tome primero.

Las herramientas aparecen cuando la sesión está en vivo y desaparecen al terminar.

El agente de IA

SentinelDesk expone 134 herramientas por un socket Unix local usando el Model Context Protocol. Un host de IA — Claude Code, Claude Desktop, o cualquier cosa que hable MCP — se conecta a través de un puente delgado:

docker exec -i sentineldesk sentineldesk -mcp-stdio

Matar el host de IA no se lleva el escritorio con él. El socket es 0600 y local al contenedor.

Cómo conectar uno

El puente es un subcomando del mismo binario, ejecutado con docker exec. En la configuración de tu cliente MCP:

{
  "mcpServers": {
    "sentineldesk": {
      "command": "docker",
      "args": [
        "exec", "-i", "-u", "sentineldesk", "sentineldesk",
        "/usr/local/bin/sentineldesk", "-mcp-stdio",
        "-mcp-sock", "/run/user/1000/sentineldesk-mcp.sock"
      ]
    }
  }
}

-i mantiene stdin abierto, que es el transporte; -u sentineldesk lo corre como el dueño del socket.

Las herramientas cubren mouse y teclado, ventanas, ejecución de comandos, capturas y grabación, el navegador vía DevTools, el árbol de accesibilidad — para que el agente lea lo que hay en pantalla como estructura y no como píxeles — archivos, paquetes, SSH, y la sala misma.

Encontrar la herramienta correcta

Ciento quince descripciones de herramientas son una porción real de la atención de un modelo, gastada antes de leer tu pedido. tool_search es la salida: describís la tarea y te devuelve el puñado de herramientas que la hacen, con sus esquemas de entrada incluidos para poder llamarlas enseguida.

{"name": "tool_search", "arguments": {"query": "dar acceso remoto a alguien"}}

Eso devuelve las herramientas ssh_*, ordenadas por relevancia, cada una con su nivel de riesgo y su esquema. Para pedir un tema entero usá {"category": "ssh"} — los temas son ssh, shell, terminal, browser, accessibility, windows, input, screen, files, processes, packages, snapshot, recording, restream, room, audio, clipboard, desktops, system y general.

Buscar sólo ahorra algo si hay algo que no se está listando, y la mayoría de los hosts de IA ya lo resuelven por su cuenta — Claude Code difiere los esquemas y los carga a demanda. Para los que no, poné MCP_DISCOVERY=1: la lista de herramientas pasa a anunciar un conjunto base de doce — suficiente para mirar el escritorio, leer su estructura, hacer clic, escribir y ejecutar algo — y deja que tool_search saque el resto a la luz.

Todas las demás siguen siendo llamables. El descubrimiento acota lo que se anuncia, nunca lo que se permite; de eso se encarga la política, más abajo. Una herramienta que quedó fuera de la lista es una de la que al agente todavía no le hablaron, no una que tenga prohibida.

Limitar lo que puede hacer

Cada herramienta declara qué puede hacerle a la máquina, y los niveles de política se apoyan en esa única declaración:

RiesgoQué significaEjemplo
readObserva; no cambia nada screenshot, ui_tree
writeManeja el escritorio — entrada, ventanas, volumen, portapapeles — pero no llega al sistema que hay debajo mouse_click, type_text
dangerEjecuta código, toca el sistema o saca datos hacia afuera run_command, ssh_exec

Una conexión puede restringirse más a sí misma, pero nunca ampliarse — y eso es lo que hace seguro darle a un agente un extremo de sólo lectura sin cambiarle nada a nadie más.

Los niveles de riesgo también se publican como las anotaciones readOnlyHint y destructiveHint del propio Model Context Protocol, así que un host de IA que las entienda puede decidir por su cuenta cuándo preguntarte antes de actuar — sin saber nada de SentinelDesk.

La TUI: manejar el agente desde una terminal

El panel de chat del navegador es una cara del agente. La otra es una sesión de terminal, y es la que tiene todo: el selector de modelo, el panel de costos, los pedidos de aprobación. Abrila en el contenedor del agente:

docker exec -it sentineldesk-agent sentineldesk-agent

Sin argumentos encuentra el socket, abre una sesión y espera. Cada tarea que escribís conserva el contexto de la anterior, así que es una conversación y no una serie de preguntas sueltas. Las dos caras son vistas de la misma sesión: lo que hacés acá aparece en el panel del navegador.

Qué podés escribir

Todo lo que no sea un comando con barra se le manda al agente — como tarea nueva, o como corrección si ya hay una corriendo. Escribir / abre una paleta que autocompleta, así que no hay que memorizar nada.

/rewind mueve la conversación, no la máquina

Vuelve la transcripción a antes de una tarea, que es la salida barata cuando el modelo se fue por el camino equivocado cinco turnos atrás. Lo que no puede es deshacer lo hecho: los paquetes siguen instalados, las ventanas abiertas, los archivos escritos. Al agente se le dice en el mismo aliento, y el registro de auditoría es append-only y no se rebobina — lo que pasó, pasó. Para un undo real de la máquina, tomá antes un punto de restauración con snapshot_create.

Aprobar lo que hace

Arrancá con -mode ask y cada llamada que cambia algo se detiene primero. Las lecturas pasan sin molestar, a propósito: una confirmación por cada captura entrena a la persona a apretar y sin leer, y una confirmación que nadie lee es peor que ninguna.

docker exec -it sentineldesk-agent sentineldesk-agent -mode ask
tecla
ypermitir esta llamada
nrechazarla — se le dice al agente que no busque otra vuelta
apermitir llamadas como ésta por el resto de la corrida
tpermitir esta herramienta por el resto, con cualquier argumento

a se ata al nombre entendible del comando, así que aprobar apt install nginx también cubre apt install curl y no cubre rm. Un comando encadenado o con redirección nunca se generaliza: aprobar apt update no puede convertirse en aprobar apt update && rm -rf /.

Los permisos viven por la corrida y nunca llegan al disco — uno que sobreviviera a la sesión sobreviviría a la razón por la que alguien lo dio. Cada permiso, y cada llamada posterior que lo usó, quedan en el rastro: «¿por qué no me preguntó?» se responde después.

Acotar una corrida

sentineldesk-agent -run "instalá nginx y mostrame que anda" \
  -max-turns 40 -max-spend 0.50 -max-time 10m -mode ask

-max-turns es un punto de control, no un muro: al llegar se le pregunta al modelo si más pasos terminarían el trabajo, y detrás hay un techo duro que no puede negociar. -max-spend y -max-time son techos — terminan la corrida con lo que tenga, no la apuran.

Leer qué pasó

sentineldesk-agent -history          # todas las corridas, con turnos, llamadas y costo
sentineldesk-agent -history 42       # una corrida completa
sentineldesk-agent -export 42        # la sesión entera por stdout
sentineldesk-agent -costs            # cuánto se gastó, y en qué
sentineldesk-agent -resume 42        # retomarla; 0 es la más reciente

-history <id> muestra el plan del propio modelo al lado de lo que realmente hizo, nombra qué agente actuó cuando se delegó una subtarea, y dice claramente por qué se detuvo — blocked · over-budget, en vez de dejarte inferirlo de un contador de turnos que casualmente da el límite.

-resume redibuja la conversación y le dice al modelo cuánto hace que paró, y que el escritorio siguió corriendo sin él. Eso importa más de lo que suena: esto no es un agente de código retomando archivos que siguen donde los dejó — se cerraron ventanas, alguien más puede tener los controles, y la pantalla que recuerda es una fotografía.

Antes de gastar nada

sentineldesk-agent -doctor                          # 15 chequeos contra el escritorio real, sin modelo
sentineldesk-agent -tools "auditar el firewall"     # qué se le ofrecería, y su ranking
sentineldesk-agent -skills                          # las skills encontradas, y de dónde salió cada una
sentineldesk-agent -providers                       # qué modelos se pueden alcanzar, y qué necesita cada uno

-doctor es lo primero que hay que correr cuando algo anda mal. Habla con el escritorio real, no involucra modelo y no cuesta nada. Si falla, el problema no es la clave.

Correrlo en el host

El agente encuentra solo el socket en el volumen sentineldesk-run, así que no tiene por qué estar en un contenedor:

docker compose up -d sentineldesk   # solo el escritorio
sentineldesk-agent -serve           # el agente, en el host

Es la forma más liviana de trabajar mientras cambiás el agente — no hay imagen que reconstruir entre ediciones. No corras los dos: dos runtimes en un escritorio significa que gana la conexión más nueva y la vieja se cae. No se rompe nada; solo confunde. Elegí uno.

Qué viene instalado, y las dos imágenes

De una misma construcción salen dos variantes. Lite es la de por defecto; full agrega lo que es demasiado grande o demasiado específico como para dárselo a todo el mundo.

Acá «lite» no significa sin escritorio — en una Raspberry Pi eso es justamente lo que significa, pero acá el escritorio es el producto. Significa el conjunto más chico que no te deja buscando un gestor de paquetes la primera tarde: un navegador, un editor de texto, visores de imágenes y documentos, gestor de archivos comprimidos, calculadora y monitor de procesos, más las herramientas de red para las que este escritorio suele existir — nmap, dig, iperf3, tcpdump, mtr, sngrep y un cliente OpenVPN. También está Git, porque todo el mundo clona algo.

Full suma LibreOffice, Firefox, GIMP, Wireshark, un entorno de compilación y Go, y en máquinas Intel también Steam y Wine.

Que Go esté en full y no en lite es a propósito, aunque este proyecto esté escrito en Go. Un toolchain son 250 MB para gente que nunca va a escribir go, y «todo el mundo clona algo» es una afirmación que se sostiene para git y no para un compilador.

Full contiene a lite

Full se construye encima de lite y no al lado, así que todo lo que está en una está en la otra. Además comparten casi todo su almacenamiento: una máquina que ya tiene lite se descarga sólo la diferencia.

Encontrar las cosas

El menú está agrupado por lo que querés hacer. Terminal, Navegador, Archivos y Editor de texto están arriba porque son los que se abren todas las sesiones; Accesorios, Red y Herramientas del sistema tienen el resto, y Todas las aplicaciones lista todo lo instalado.

Las entradas de línea de comandos dentro de Red abren una terminal con la sintaxis de la herramienta ya impresa, así no tenés que ir a buscar los parámetros primero.

Conectarse a una VPN

Red → VPN te pide un perfil .ovpn y conecta. Los perfiles guardados en ~/.openvpn se ofrecen directamente, y el home sobrevive a los reinicios: una conexión que configurás una vez queda configurada.

Esto necesita que el contenedor se haya levantado con dispositivo de túnel y privilegios de red. Si no los tiene, el cuadro de diálogo lo dice y muestra las dos líneas que hay que agregar, en vez de fallar en silencio.

Reloj y teclado

Los dos se fijan cuando arranca el escritorio, así una sola imagen sirve para cualquier región. El reloj sigue a TZ — cualquier nombre estándar, por ejemplo America/Argentina/Buenos_Aires — y el teclado a KEYBOARD_LAYOUT: us, es para España, latam para Latinoamérica, y así.

Si alguno está mal escrito se avisa y se ignora, en lugar de quedar aplicado a medias. Un reloj corriendo en UTC en silencio por un tipeo es peor que uno que te lo dice.

Cuando algo no anda

No llega nada a VLC

Casi siempre es una de tres cosas. Revisalas en este orden:

  1. VLC no está escuchando de verdad. lsof -nP -iUDP:5000 tiene que mostrar UDP *:5000. Un puerto alto al azar significa que está llamando hacia afuera, no escuchando — te faltó el @.
  2. La dirección apunta a un lado al que el contenedor no llega. Desde adentro de Docker, localhost es el contenedor mismo, y una dirección del host que caiga en 172.17.0.0/16 choca con el propio bridge de Docker.
  3. Estás usando srt:// con VLC. Mirá más arriba.

La interfaz no cambió después de recompilar

Debería — el cliente se sirve con un ETag sobre sus propios bytes, así que el navegador está obligado a revalidar. Si igual persiste, confirmá que el contenedor se recreó y no que sólo se reinició: make up reconstruye la imagen.

La imagen se ve blanda, o va atrasada

Abrí Estadísticas. Muestra el bitrate en vivo, cuadros, paquetes, cuánto estás atrás del vivo, y un reloj con milisegundos — que es la forma más rápida de saber si dos navegadores están realmente sincronizados.

La causa habitual es codificar 1080p por software. Poné ENCODER=x264 si la detección automática cayó en VP8, y fijate si el host tiene una GPU que valga la pena usar con nvenc o vaapi.

Las teclas no llegan al escritorio

Mirá el panel de presencia: sólo el participante que tiene el control manda entrada. Y si hay una ventana de la capa de control abierta, el teclado es de ella, no del escritorio.
