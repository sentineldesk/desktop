SentinelDesk

Um sistema operacional colaborativo para pessoas e agentes de IA. Uma área de trabalho Linux, num contêiner, que os dois operam — vendo a mesma tela, se revezando, e lendo os erros um do outro.

Essa segunda metade não é uma metáfora para uma API. É o mesmo display X, a mesma sessão, a mesma sala:

  • O agente é um participante, não um processo em segundo plano. Ele tem um nome na lista e um ponteiro na tela com a sua própria cor, para que nunca seja ambíguo se o mouse foi movido por um colega ou pelo modelo.
  • Eles se revezam. O controle é pedido, nunca presumido — por qualquer um, agente incluído, havendo alguém assistindo ou não. Ninguém tem os controles até pedir, então entrar para assistir não lhe deixa um desktop que você não queria. Quando alguém está dirigindo, pedir coloca um aviso na tela dessa pessoa e não responder significa não.
  • Eles leem o mesmo estado. Todo comando executado num terminal informa seu código de saída, seja quem for que o rodou, então uma pessoa pode esbarrar num erro e pedir ao agente que olhe o que de fato aconteceu.
  • Uma captura, muitos observadores. A área de trabalho é codificada uma única vez e distribuída: para cada navegador, para a gravação, para uma transmissão ao vivo. Um participante a mais custa banda, não CPU.

As pessoas a operam por uma camada de controle no navegador. O agente a opera por um socket local com 134 ferramentas MCP. Nenhum é convidado do outro.

Sobre o que é construído

Um único binário Go. O GStreamer roda dentro do processo via go-gst e não como um filho dele, então o codificador continua acessível em tempo de execução — o bitrate segue a rede, os quadros-chave respondem a um pedido, e um destino externo se conecta sem parar nada.

Instalar e colocar no ar

Tudo roda num contêiner. Nas máquinas que se conectam não há nada a instalar — o cliente é o navegador.

O que é preciso

  • Docker com Compose v2. Docker Desktop no macOS e no Windows, Docker Engine no Linux.
  • 2 GB de RAM e dois núcleos para um 1080p30 confortável. A GPU é opcional e muda muito — veja Aceleração por hardware.
  • amd64 para o Steam e o Wine, que estão apenas na imagem full. Todo o resto roda também em arm64, nas duas imagens.

Formas de iniciar

A forma de um único comando, em um VPS, um Raspberry Pi ou qualquer host Linux. Instala o Docker se faltar, baixa a imagem publicada do Docker Hub e deixa a área de trabalho rodando em segundo plano — nada para clonar, nada para compilar.

curl -fsSL https://raw.githubusercontent.com/sentineldesk/desktop/main/install.sh | sudo bash

Adicione --full para a imagem mais pesada, --pass <p> para definir a senha e --ip <addr> em um VPS público para que o vídeo seja alcançável. --help lista todas as opções.

As imagens publicadas, dois serviços, um comando. Baixe o arquivo e suba — sem clonar, sem compilar:

curl -fsSLO https://raw.githubusercontent.com/sentineldesk/desktop/main/docker-compose.yml
AUTH_PASS=cambiame HOST_IP=192.168.0.100 docker compose up -d

HOST_IP es la dirección por la que los navegadores llegan a esta máquina — su IP de la LAN, o la pública en un VPS. Fuera de localhost es obligatoria y no opcional: si no, WebRTC anuncia la IP del bridge del contenedor, que nada de afuera alcanza, y la página se queda en «Estableciendo WebRTC» con el video en negro. Después abrí https://192.168.0.100:8080.

Poné SENTINELDESK_TAG=full para la imagen pesada.

Qué levanta

serviciocontenedorqué es
sentineldesksentineldesk el escritorio: X, el navegador, las apps, el stream WebRTC, el servidor MCP
agentsentineldesk-agent el runtime que lo maneja — el cerebro detrás del panel de chat

El agente es opcional, y nombrar al escritorio es cómo se dice eso:

docker compose up -d                # el escritorio y un agente al lado
docker compose up -d sentineldesk   # el escritorio solo

El escritorio no tiene depends_on ni ningún vínculo con el agente, así que la segunda línea es un despliegue completo y no uno mutilado. El orden tampoco importa: si arranca primero, el agente espera al escritorio y se reconecta cuando vuelve.

Cómo se unen los dos

Un volumen, sentineldesk-run, con sockets Unix y montado en ambos. Ese es el único vínculo entre ellos. El agente no tiene puertos ni red propia, así que nada de la conversación sale de esta máquina — y el agente solo puede hacer lo que ese socket concede, que es por qué acá hay un borde de seguridad y no dos.

volumenqué guarda
sentineldesk-homeperfiles del navegador, archivos, el certificado TLS
sentineldesk-auditel registro de acciones — aparte, para que borrar un perfil nunca se lleve el registro
sentineldesk-agentel modelo elegido, las claves y el historial del agente
sentineldesk-workespacio temporal para capturas y grabaciones en curso

Comandos de todos los días

docker compose ps                      # qué está arriba
docker compose logs -f sentineldesk    # seguir el escritorio
docker compose logs -f agent           # seguir el agente
docker compose restart agent           # reiniciar un servicio
docker compose down                    # parar ambos, conservar los volúmenes
docker compose pull && docker compose up -d    # actualizar en el lugar

down no toca los volúmenes, así que el home, el registro y las claves del agente sobreviven. Para empezar realmente de cero, borralos por nombre — y leelo como el comando destructivo que es: docker volume rm sentineldesk-home sentineldesk-agent.

Configurarlo

Compose lee un .env al lado del archivo, que es el lugar más prolijo para lo que si no repetirías en la línea de comandos:

AUTH_USER=admin
AUTH_PASS=una-clave-de-verdad
HOST_IP=192.168.0.100
SENTINELDESK_TAG=latest        # o `full`
TZ=America/Argentina/Buenos_Aires
KEYBOARD_LAYOUT=latam
HTTP_PORT=8080

Todas tienen un valor por defecto; solo AUTH_PASS y HOST_IP conviene fijarlas antes de que alguien más pueda llegar al despliegue.

HTTPS viene por defecto

El escritorio sirve TLS de fábrica: sin configurar nada genera un certificado autofirmado una vez, lo guarda en el volumen del home, y el navegador te pide aceptarlo exactamente una vez. Tu propio certificado gana con TLS_CERT/TLS_KEY. Es más que el candadito: los navegadores solo permiten el micrófono y el portapapeles rico en orígenes seguros, así que un escritorio por HTTP plano perdía funciones en silencio.

Para terminar TLS vos mismo con un proxy adelante — nginx, Caddy, Nginx Proxy Manager — poné TLS_SELFSIGNED=0 para que el backend hable HTTP plano con el proxy.

Un relay para redes hostiles

El peer-to-peer falla en NAT simétrica y donde se descarta UDP. Hay un servicio TURN en el archivo, apagado por defecto, porque un relay lleva cada cuadro de cada sesión por adentro y pagar eso cuando nadie lo necesita es el intercambio equivocado:

docker compose --profile turn up -d

Poné CLIENT_TURN_URLS en el escritorio cuando esté corriendo, o a los navegadores nunca se les dice que el relay existe.

La VPN incorporada

El escritorio puede discar OpenVPN, que necesita un dispositivo túnel y la capacidad de configurar rutas. Los dos están comentados en el compose — descomentá cap_add: NET_ADMIN y devices: /dev/net/tun en el servicio sentineldesk. NET_ADMIN deja al contenedor manejar su propia pila de red, que es un permiso real, así que dejalo apagado en un despliegue que nunca vaya a discar una.

Para mexer no código — o caminho de quem contribui. A imagem é construída a partir da raiz do repositório para que o Dockerfile alcance tanto as fontes Go quanto os assets da área de trabalho.

# verificação rápida de tipos no host, sem contêiner
go build ./...
# construir as duas variantes
make image
# ou apenas uma delas
make image-lite
make image-full
# ou, sem make — atenção ao --target
docker build -f deploy/Dockerfile --target desktop -t sentineldesk:latest .

--target desktop não é opcional. A última etapa do Dockerfile é full, então omiti-lo constrói LibreOffice, Firefox, GIMP, Wireshark e todo o resto — uns 2,5 GB — e depois marca isso como sentineldesk:latest, um nome que em todos os outros lugares significa lite.

A interface web vai embutida com go:embed, então mexer em qualquer coisa dentro de internal/webui/assets/ obriga a reconstruir a imagem — a mudança não aparece recarregando a página.

As duas imagens

Um único Dockerfile produz as duas. Lite é a padrão e é para onde :latest aponta:

TagTambémO que é

A full é construída em cima da lite

Então tudo o que uma tem está na outra, e as duas compartilham todas as camadas até o ponto onde se separam: uma máquina que já tem a lite baixa apenas a diferença. O que vem instalado percorre o que cada uma carrega e por quê.

A primeira vez

Abra https://localhost:8080 (autoassinado — aceite o aviso do navegador uma vez). Com AUTH_USER e AUTH_PASS definidos ele pede login; sem eles fica aberto.

# acompanhar os logs da área de trabalho
docker logs -f sentineldesk
# um shell de root dentro do contêiner
docker exec -it -u root sentineldesk bash
# parar e remover (o volume do home é mantido)
docker rm -f sentineldesk

A partir de um checkout do código, os mesmos três são make logs, make shell e make down.

A área de trabalho guarda seu home num volume nomeado, sentineldesk-home, então os perfis do navegador, os aplicativos instalados e a biblioteca do Steam sobrevivem a um reinício ou a uma recompilação.

A resolução não é o binário que muda

DISPLAY_WIDTH e DISPLAY_HEIGHT são lidas pelo Xvfb ao iniciar, não pelo servidor. Por isso a área de trabalho pode ser reduzida em tempo de execução mas nunca ampliada além do reservado no boot — e por isso mudá-las implica reiniciar o contêiner.

Flags de linha de comando

O binário aceita nove. Cinco são do lado da IA; as outras quatro fazem do binário a sua própria distribuição. Todo o resto é variável de ambiente, porque todo o resto é configuração de um serviço e não uma decisão tomada a cada invocação.

FlagDescrição
-mcp-sock <caminho>O socket Unix onde o servidor MCP escuta. Vazio significa que o servidor MCP não inicia. Por padrão usa MCP_SOCK
-mcp-stdioRodar como ponte stdio em vez de como área de trabalho: conecta-se a -mcp-sock e retransmite JSON-RPC entre o stdin/stdout do host de IA e esse socket
-mcp-policy <nível>full, safe ou readonly — só para esta ponte
-mcp-deny <lista>Ferramentas que esta ponte não pode usar, separadas por vírgula. Um * no fim casa por prefixo
-mcp-allow <lista>Uma lista branca exclusiva para esta ponte

As três últimas restringem uma conexão, em cima do que MCP_POLICY já permite. Uma ponte pode se estreitar mas nunca se ampliar — e é isso que torna seguro dar a um agente um ponto de acesso somente leitura sem mudar nada para os outros:

docker exec -i -u sentineldesk sentineldesk \
  /usr/local/bin/sentineldesk -mcp-stdio \
  -mcp-sock /run/user/1000/sentineldesk-mcp.sock \
  -mcp-policy safe -mcp-deny 'ssh_*,install_packages'

Aceleração por hardware

O codificador é escolhido na inicialização rodando um pipeline de teste real para cada candidato, então o que você obtém reflete o que de fato funciona naquele host e não o que os drivers alegam. Force um com ENCODER=nvenc|vaapi|h264|vp8.

Para usar uma GPU, passe o dispositivo ao contêiner. Para VA-API adicione --device /dev/dri e a sonda a escolhe sozinha. NVENC precisa do NVIDIA Container Toolkit e de --gpus all; sem uma GPU utilizável a área de trabalho cai para codificação por software.

Por que x264 e não VP8 sem GPU

Medido sobre conteúdo de área de trabalho, o libx264 em veryfast sustenta 1080p por cerca de um terço do que o vp8enc precisa, e H.264 é o que todo navegador decodifica por hardware. Isso também importa do lado que recebe: um cliente que não dá conta parece uma rede congestionada para o estimador, e arrasta o bitrate da sala inteira para baixo.

Produção

O modelo de segurança

É curto de enunciar: o WebSocket é a única porta.

A primeira mensagem do WebSocket tem que ser uma de autenticação com usuário e senha, ou com um token de sessão. Até validar não há handshake de WebRTC nenhum — nem oferta SDP, nem ICE, nem DataChannel. Um token inválido, uma oferta tentando pular a autenticação, ou silêncio passados os dez segundos, fecham a conexão.

Falhas repetidas da mesma origem são limitadas e depois bloqueadas por um tempo, então uma senha não é algo que se possa adivinhar rápido.

  • Defina AUTH_SECRET com um valor fixo. Sem definir é aleatório, e cada reinício invalida a sessão de todos.
  • FILES_ROOT limita até onde o gerenciador de arquivos alcança. Deixe dentro do home a menos que queira outra coisa.
  • Os downloads viajam com um tíquete de uso único na URL em vez do token de sessão, então um link que vazar já está gasto.
  • O socket MCP é 0600 e local ao contêiner. Nunca é exposto pela rede.

TLS

A área de trabalho serve HTTPS por conta própria. Sem nada configurado gera um certificado autoassinado no primeiro início e o guarda no volume do home; TLS_HOSTS coloca os nomes certos nele. Para usar o seu, passe TLS_CERT e TLS_KEY (um sem o outro se recusa a iniciar). Para terminar o TLS num proxy reverso na frente — nginx, Caddy — defina TLS_SELFSIGNED=0 para o backend falar HTTP puro com o proxy. De qualquer forma o cliente muda para wss:// sozinho. Isso importa além do cadeado: o microfone e a área de transferência rica só funcionam numa origem segura.

TURN no macOS e no Windows

O Docker Desktop roda o contêiner dentro de uma VM, então os endereços que o ICE descobre são os da VM e não são alcançáveis, e pode não se formar uma conexão direta. Um relay TURN fecha essa lacuna — aponte o navegador para um com CLIENT_TURN_URLS (e TURN_USER / TURN_PASS). Num host Linux com as portas acima publicadas, nada disso é necessário.

Atualizar e o estado

Reconstruir substitui a imagem; não toca no home.

git pull
make up

O que sobrevive vive no volume nomeado sentineldesk-home: perfis do navegador, aplicativos que você instalou, a biblioteca do Steam, o certificado autoassinado. O que não, é qualquer coisa escrita fora do home dentro do contêiner — isso vai embora com a imagem antiga.

Para começar do zero, e perder tudo isso:

make down
docker volume rm sentineldesk-home
Recompilou e continua vendo a interface antiga

Não deveria acontecer: o cliente é servido com um ETag sobre os próprios bytes, então o navegador é obrigado a revalidar. Se ainda assim acontecer, confirme que o contêiner foi recriado e não apenas reiniciado — make up reconstrói e recria.

A camada de controle

Tudo o que se opera fica numa barra à esquerda da janela do navegador. Ela flutua sobre o vídeo ao vivo de uma área de trabalho real, então é translúcida de propósito: o que ela cobre é área de trabalho que você deixa de ver.

Com º ela aparece e desaparece. Essa tecla nunca chega à área de trabalho remota.

GrupoO que tem
CapturaMicrofone, captura de tela, gravação, transmitir
SessãoArquivos, áudio sim/não, estatísticas
VisualizaçãoTela cheia, idioma

As janelas desta camada — o gerenciador de arquivos, as estatísticas, a transmissão — continuam abertas enquanto você usa a barra, são arrastadas pelo título e fecham só pelo próprio ×. Duplo clique no título recentraliza a que ficou num lugar ruim.

Compartilhar a sessão

Uma área de trabalho, vários participantes. O modelo é o de um console compartilhado: exatamente um participante tem o controle por vez e o resto assiste. A captura é codificada uma única vez e enviada a todos, então um espectador a mais custa banda, não CPU.

Assumir e liberar o controle

O painel de presença no topo da barra diz em qual dos três estados você está: você está dirigindo, outra pessoa está, ou ninguém está. Entre pessoas o controle é cooperativo — qualquer um pode assumir, e quem tinha vê a mudança na hora. Não há hierarquia, porque todos entraram com a mesma credencial.

Entrar não lhe dá o controle. O desktop começa sem ninguém dirigindo e continua assim até que alguém peça, então abri-lo para ver um colega trabalhar é algo que você pode fazer sem tirar a máquina de baixo dele. Toque em Assumir controle quando realmente quiser.

Liberar deixa os controles livres; não os passa ao próximo. «Terminei» e «é a sua vez» são frases diferentes, e só a primeira é verdadeira alguma vez. O mesmo vale se quem dirige simplesmente fecha a aba: os controles ficam livres em vez de cair sobre quem está conectado há mais tempo.

A barra flutuante

Uma barra na parte de baixo da tela diz a todos como está a situação, e leva o botão: verde quando os controles estão livres, âmbar quando outra pessoa está dirigindo. Ela fica enquanto isso for verdade em vez de passar rápido — o momento em que o agente termina uma tarefa é justamente quando você pode estar olhando para outro lado.

Quem é quem: tintas e ponteiros

Cada participante recebe uma cor ao entrar — amarelo o primeiro, depois ciano, magenta e quase-preto — e o violeta sempre é o agente de IA, nunca uma pessoa. Os pontos da lista a vestem, e o ponteiro também: enquanto você assiste, o seu mouse sobre a área de trabalho é desenhado lá para os outros, com o seu nome e na sua tinta — apontar coisas funciona sem tomar o controle. As gravações e as transmissões de saída incluem esses ponteiros, porque são desenhados na própria área de trabalho.

A vez do agente de IA

O agente é um participante como qualquer outro: um nome na lista e um ponteiro na tela com a sua própria cor, para que nunca seja ambíguo se o mouse foi movido por um colega ou pelo modelo.

A regra é uma linha: o controle é pedido, nunca presumido. Isso vale para o agente havendo alguém assistindo ou não — uma sala vazia era um passe livre e deixou de ser. Pedir não custa nada quando os controles estão livres, porque a resposta volta na hora; o que se ganha é uma sala que sempre sabe quem tem o desktop. Quando alguém ESTÁ dirigindo, o agente tem que pedir a essa pessoa — aparece um aviso na sua tela com um temporizador esvaziando, e não responder é não.

Ler os erros do outro

Todo comando executado num terminal desta área de trabalho informa seu código de saída, seja quem for que o rodou. Assim uma pessoa pode esbarrar num erro, pedir ao agente que olhe, e o agente lê o que realmente aconteceu em vez de ouvir um relato.

Falar com o agente pelo navegador

O botão redondo no topo da barra abre um chat ao lado da área de trabalho: a tela se divide, a área de trabalho à esquerda e a conversa à direita. Você pede algo com suas palavras, o agente trabalha, e você vê o que ele faz enquanto ele faz — cada ferramenta que ele chama aparece sob a resposta, alinhada com o que se move na tela ao lado.

O ponto no botão diz se há com quem falar antes de você apertá-lo: verde pronto, âmbar em execução mas sem modelo configurado, cinza não está.

É preciso ter o agente

A área de trabalho funciona sozinha; o agente é opcional e vive em seu próprio repositório. O painel distingue três situações e para cada uma mostra o comando que a resolve — não instalado, instalado mas não em execução, ou em execução sem modelo. Copie a linha, execute, e o painel fica verde sozinho: nada para recarregar.

A área de trabalho nunca depende dele

Um agente ausente, uma chave de API vencida, um loop que não termina: cada um custa o painel de chat e nada mais. A área de trabalho inicia igual, a sessão continua, e reiniciar o agente não toca nem o vídeo nem quem estiver assistindo. Com AGENT_ENABLED=0 o plano inteiro fica desligado.

Trabalha em automático, e mesmo assim pede o controle

Pelo chat o agente age sem perguntar a cada passo — é para isso que ele existe. O que não muda é a regra da área de trabalho: se você está no comando, ele tem que pedir, com o mesmo aviso de sempre. E quando decide consultar você antes de fazer algo, pergunta no chat, onde você está olhando.

Um único histórico

As conversas do painel e as do terminal são as mesmas: ficam guardadas na mesma base e o botão de histórico lê essa. Uma tarefa que você começou digitando no terminal aparece no navegador, e vice-versa.

Capturas e gravação

As duas estão no grupo Captura, e as duas passam pelo servidor e não pelo navegador. Isso significa que o arquivo sai com a qualidade do framebuffer, sem a compressão da transmissão — e em MP4, que abre em qualquer sistema operacional sem instalar nada. Também há WebM e MKV.

Os ponteiros dos outros participantes são desenhados sobre o próprio display X, então aparecem nas capturas e gravações do mesmo jeito que na tela.

Transmitir a área de trabalho para fora

Transmitir, no grupo Captura, envia a sessão ao vivo para outro lugar: YouTube, Twitch ou Facebook com apenas a chave de transmissão, ou um endereço completo para um VLC ou OBS seu.

Ele reaproveita a codificação que a sala já está produzindo. Entrar ao vivo não interrompe o que os outros estão vendo, e um destino a mais custa um multiplexador e um socket em vez de uma segunda captura da tela. O multiplicador que é real é a banda: cada destino leva o fluxo inteiro para fora da máquina.

Quem tem o controle decide, e a lista de destinos é vista pela sala toda — uma sessão sendo transmitida não é algo para se descobrir depois. As chaves de transmissão são censuradas antes de chegar a qualquer navegador ou log.

YouTube, Twitch, Facebook

Escolha a plataforma e cole apenas a chave de transmissão. O endereço de ingestão já é conhecido, então não há nada a procurar.

Assistir no VLC

Dois passos, nesta ordem: primeiro coloque o VLC para escutar, e só então aperte Entrar ao vivo. Se não houver ninguém escutando, a área de trabalho não tem para onde enviar.

Passo 1 — colocar o VLC em modo de escuta na sua própria máquina:

O VLC não deixa um comando vlc; é preciso chamar o binário que está dentro do aplicativo.

"/Applications/VLC.app/Contents/MacOS/VLC" \
  --network-caching=200 "udp://@:5000"
vlc --network-caching=200 "udp://@:5000"

Do PowerShell ou do prompt de comando:

"C:\Program Files\VideoLAN\VLC\vlc.exe" ^
  --network-caching=200 "udp://@:5000"

O @ é o que faz o VLC escutar em vez de conectar — sem ele nada acontece e nenhum erro é impresso. --network-caching=200 baixa o buffer dele de um segundo para 200 ms; se deixar de fora, você vai culpar a transmissão por um atraso que é do VLC.

Você pode conferir que ele está mesmo escutando:

# Linux / macOS — deve mostrar UDP *:5000, não uma porta alta aleatória
lsof -nP -iUDP:5000

Passo 2 — na barra, escolha VLC / OBS e informe o endereço:

Onde o Docker rodaEndereço a usar
Docker Desktop, mesma máquina que o VLC (macOS, Windows) udp://host.docker.internal:5000
Docker no Linux, mesma máquina que o VLC udp://172.17.0.1:5000
Outra máquina udp://<IP dessa máquina>:5000

Deixe Espectadores podem entrar a qualquer momento desmarcado. É um receptor seu — ele não precisa de um quadro-chave a cada dois segundos, e os bits economizados voltam a manter o texto legível.

Por que udp:// e não srt:// para o VLC

O VLC 3 fala SRT apenas como chamador: ele consegue conectar para fora, mas não consegue receber uma conexão, e o ?mode=listener é ignorado em silêncio. Se apontar o SentinelDesk para ele por SRT, os dois lados acabam chamando, nenhum atende, e nada é registrado porque nada falhou. Para o VLC use udp://.

Assistir no OBS

Adicione uma Fonte de Mídia, desmarque Arquivo local, e coloque o mesmo udp://@:5000 no campo de entrada. O OBS também aceita srt://, em modo de escuta.

Qual protocolo usar

EsquemaPara quê
udp://Um reprodutor na sua rede. Funciona em todo lugar, não há nada a negociar.
srt://Um receptor pela internet que escuta: um servidor SRT, OBS em modo de escuta. Recupera-se de perda de pacotes; numa LAN não acrescenta nada.
rtmp://, rtmps://As plataformas. Antigo e desajeitado, e a única coisa que elas aceitam.

Sobre os quadros-chave

Um espectador não vê nada até chegar um quadro-chave, então uma plataforma que atende gente que aparece a qualquer momento precisa de um a cada dois segundos. Isso é aplicado sozinho enquanto houver um destino desses conectado, e volta a ser sob demanda assim que o último para.

Quadros-chave são de dez a cinquenta vezes maiores que um normal, e cada bit que ocupam é um bit que não foi gasto no texto da sua tela. Um receptor que você mesmo inicia pode simplesmente esperar pelo primeiro, e por isso a imagem fica mais nítida.

Somente H.264

Nenhum destino de transmissão aceita VP8. A detecção automática do codificador prefere x264 a VP8, então normalmente isso já é verdade; num host onde não for, defina ENCODER=x264.

O endereço fica guardado

O que você digita fica guardado neste navegador, por destino, então reabrir o painel durante a transmissão mostra o que está sendo enviado e parar não significa colar a chave de novo. É guardado do mesmo jeito que um navegador guarda uma senha: nesta máquina, para este site, e em nenhum outro lugar.

Mover arquivos

Arquivos, no grupo Sessão, abre um gerenciador de dois painéis: a área de trabalho remota à esquerda, a sua máquina à direita. As teclas de função embaixo fazem o de sempre — F5 copiar, F6 renomear, F7 nova pasta, F8 excluir, F2 atualizar.

Você também pode soltar arquivos em qualquer parte da página para enviá-los à área de trabalho, sem abrir o gerenciador.

Os downloads viajam com um tíquete de uso único na URL em vez do seu token de sessão, então um link que vazar já está gasto e não serve. FILES_ROOT limita até onde o gerenciador alcança.

Seu microfone, na área de trabalho

Microfone, no grupo Captura, envia seu microfone para o contêiner, onde os aplicativos o veem como um dispositivo de entrada real — e não como o monitor de algo que está tocando, que é o que os navegadores escondem do seu seletor de microfones. Qual ele usa se escolhe em Ajustes — a engrenagem no trilho, ou clique direito sobre o botão.

Só o participante que tem o controle pode publicar áudio. Sua voz passa a fazer parte da área de trabalho: os aplicativos, as gravações e as transmissões de saída a escutam. Para falar com as outras pessoas da sala sem que a área de trabalho ouça uma palavra, veja Voz.

Voz, entre quem assiste

Voz, no grupo Sessão, é a outra conversa: uma conferência de voz entre as pessoas da sala, navegador a navegador. A área de trabalho nunca a ouve — as gravações, as transmissões de saída e os aplicativos lá dentro não carregam rastro dela. Imagine quatro pessoas narrando um vídeo que toca na tela compartilhada: a narração é a Voz; o som do vídeo continua sendo da área de trabalho.

Entra-se um a um, como num rádio: apertar o seu próprio botão captura o seu microfone e anuncia você, e não liga nada para ninguém mais. Quem também estiver com a Voz ativa se conecta a você direto, par a par — o áudio viaja entre navegadores, e o servidor só repassa os envelopes lacrados do cumprimento sem lê-los. Com três ou quatro pessoas é uma malha: cada par tem a sua própria conexão, todos se escutam.

Sozinho na conferência nada soa: o contador do botão mostra quantos pares estão conectados, e 0 é um estado de espera, não uma falha. A ordem também não importa — quem ativar a Voz mais tarde se anuncia e os pares se formam sozinhos. Apertar o botão de novo sai da conferência e libera o seu microfone.

Qual dispositivo cada conversa usa — o microfone da área de trabalho e o da conferência — se escolhe em Ajustes, onde um medidor de nível e o teste de se ouvir respondem "este me escuta?" antes que alguém mais precise. A Voz não precisa de controle nem de turno: assistir basta. É a conversa sobre a área de trabalho, não com ela.

Ajustes: seus dispositivos e seu nome

A engrenagem no grupo Sessão — ou o clique direito sobre Microfone — abre os Ajustes. Responde às duas perguntas que toda chamada acaba fazendo: qual dispositivo, e se ele me escuta.

Microfone e Voz se escolhem separadamente, porque são atos distintos — a entrada da própria área de trabalho e a conferência de quem assiste — e alguém com headset e microfone de mesa realmente os quer separados. O medidor de nível segue o último seletor que você tocou; Ouvir a mim mesmo reproduz a sua própria voz na saída escolhida (melhor com fones), e o teste de alto-falantes toca na saída que você escolheu. As escolhas ficam lembradas por navegador e valem na hora, mesmo no meio da sessão.

Seu nome também mora aqui: letras, números, espaço, hífen e sublinhado. Aparece na lista, no registro de auditoria da sessão e na etiqueta do ponteiro que os outros veem — defina uma vez e a sala para de chamá-lo de «Viewer 2».

O teclado na tela

Teclado, no grupo Visor, ancora um teclado completo na borda inferior da tela — feito para tablets, útil em qualquer lugar. Duas disposições (ES, espanhol ISO com ñ, ç e as teclas mortas; EN, US ANSI), teclado numérico e bloco de navegação atrás do botão 123, e uma variante compacta Mini. O botão — o guarda numa pílula embaixo ao centro; toque nela para trazê-lo de volta.

Os acentos se compõem como no teclado de um celular: toque ´ e depois uma vogal e chega um á — toque o acento duas vezes para o caractere literal. Shift, Ctrl, Alt e AltGr são travas: toque uma, toque uma tecla, e o acorde viaja. A tecla do monitor é o ⊞ desta área de trabalho — um toque abre o menu de aplicativos.

Numa tela de toque a própria área de trabalho é manipulação direta: um dedo é o ponteiro com o botão esquerdo pressionado, dois dedos rolam, e um toque rápido com dois dedos é o botão direito.

Com o teclado aberto, um teclado físico acende as suas próprias teclas à medida que você digita — o mesmo vermelho de um toque. É um «é assim que eu escrevo» ao vivo, e confirma num relance que as teclas estão chegando.

A IA do próprio navegador pode dirigi-la

Além do agente que se conecta por MCP, a área de trabalho oferece um conjunto de ferramentas à IA que o próprio navegador carrega — a emergente API de «model context» que o Gemini integrado do Chrome lê. Nada a instalar nem chave a colar: a partir do momento em que você está autenticado e conectado, a página publica suas ferramentas e o modelo do navegador pode agir através delas.

As ferramentas fazem exatamente o que você faz, pelo exatamente seu caminho: digitar, pressionar teclas, mover e clicar com o ponteiro, rolar, definir a área de transferência, tirar uma captura, listar e organizar arquivos, ajustar a qualidade, assumir ou liberar o controle. Viajam pelo mesmo DataChannel autenticado que os seus próprios cliques — sem endpoint à parte, sem segundo login. Assim a IA do navegador alcança exatamente até onde você alcança e nem um passo além: tudo o que escreve na área de trabalho espera até que o controle seja mantido, e pede ao modelo que o assuma primeiro.

As ferramentas aparecem quando a sessão está ao vivo e desaparecem ao terminar.

O agente de IA

O SentinelDesk expõe 134 ferramentas por um socket Unix local usando o Model Context Protocol. Um host de IA — Claude Code, Claude Desktop, ou qualquer coisa que fale MCP — conecta através de uma ponte fina:

docker exec -i sentineldesk sentineldesk -mcp-stdio

Matar o host de IA não derruba a área de trabalho junto. O socket é 0600 e local ao contêiner.

Como conectar um

A ponte é um subcomando do mesmo binário, executado com docker exec. Na configuração do seu cliente MCP:

{
  "mcpServers": {
    "sentineldesk": {
      "command": "docker",
      "args": [
        "exec", "-i", "-u", "sentineldesk", "sentineldesk",
        "/usr/local/bin/sentineldesk", "-mcp-stdio",
        "-mcp-sock", "/run/user/1000/sentineldesk-mcp.sock"
      ]
    }
  }
}

-i mantém o stdin aberto, que é o transporte; -u sentineldesk roda como o dono do socket.

As ferramentas cobrem mouse e teclado, janelas, execução de comandos, capturas e gravação, o navegador via DevTools, a árvore de acessibilidade — para que o agente leia o que está na tela como estrutura e não como pixels — arquivos, pacotes, SSH, e a própria sala.

Encontrar a ferramenta certa

Cento e quinze descrições de ferramentas são uma fatia real da atenção de um modelo, gasta antes de ele ler o seu pedido. tool_search é a saída: você descreve a tarefa e recebe de volta o punhado de ferramentas que a fazem, com os esquemas de entrada junto, para poder chamá-las na hora.

{"name": "tool_search", "arguments": {"query": "dar acesso remoto a alguém"}}

Isso devolve as ferramentas ssh_*, ordenadas por relevância, cada uma com seu nível de risco e seu esquema. Para pedir um tema inteiro use {"category": "ssh"} — os temas são ssh, shell, terminal, browser, accessibility, windows, input, screen, files, processes, packages, snapshot, recording, restream, room, audio, clipboard, desktops, system e general.

Buscar só economiza alguma coisa se houver algo que não está sendo listado, e a maioria dos hosts de IA já resolve isso por conta própria — o Claude Code adia os esquemas e os carrega sob demanda. Para os que não, defina MCP_DISCOVERY=1: a lista de ferramentas passa a anunciar um conjunto básico de doze — o bastante para olhar a área de trabalho, ler sua estrutura, clicar, digitar e executar algo — e deixa o tool_search revelar o resto.

Todas as outras continuam chamáveis. A descoberta restringe o que é anunciado, nunca o que é permitido; disso cuida a política, mais abaixo. Uma ferramenta que ficou fora da lista é uma sobre a qual o agente ainda não foi informado, não uma que ele esteja proibido de usar.

Limitar o que ele pode fazer

Cada ferramenta declara o que pode fazer com a máquina, e os níveis de política se apoiam nessa única declaração:

RiscoO que significaExemplo
readObserva; não muda nada screenshot, ui_tree
writeConduz a área de trabalho — entrada, janelas, volume, área de transferência — mas não alcança o sistema por baixomouse_click, type_text

Uma conexão pode se restringir mais, mas nunca se ampliar — e é isso que torna seguro dar a um agente um ponto de acesso somente leitura sem mudar nada para os outros.

Os níveis de risco também são publicados como as anotações readOnlyHint e destructiveHint do próprio Model Context Protocol, de modo que um host de IA que as entenda pode decidir sozinho quando perguntar antes de agir — sem saber nada sobre o SentinelDesk.

A TUI: usar o agente a partir de um terminal

El panel de chat del navegador es una cara del agente. La otra es una sesión de terminal, y es la que tiene todo: el selector de modelo, el panel de costos, los pedidos de aprobación. Abrila en el contenedor del agente:

docker exec -it sentineldesk-agent sentineldesk-agent

Sin argumentos encuentra el socket, abre una sesión y espera. Cada tarea que escribís conserva el contexto de la anterior, así que es una conversación y no una serie de preguntas sueltas. Las dos caras son vistas de la misma sesión: lo que hacés acá aparece en el panel del navegador.

O que você pode escrever

Todo lo que no sea un comando con barra se le manda al agente — como tarea nueva, o como corrección si ya hay una corriendo. Escribir / abre una paleta que autocompleta, así que no hay que memorizar nada.

/rewind move a conversa, não a máquina

Vuelve la transcripción a antes de una tarea, que es la salida barata cuando el modelo se fue por el camino equivocado cinco turnos atrás. Lo que no puede es deshacer lo hecho: los paquetes siguen instalados, las ventanas abiertas, los archivos escritos. Al agente se le dice en el mismo aliento, y el registro de auditoría es append-only y no se rebobina — lo que pasó, pasó. Para un undo real de la máquina, tomá antes un punto de restauración con snapshot_create.

apermitir llamadas como ésta por el resto de la corrida

a se ata al nombre entendible del comando, así que aprobar apt install nginx también cubre apt install curl y no cubre rm. Un comando encadenado o con redirección nunca se generaliza: aprobar apt update no puede convertirse en aprobar apt update && rm -rf /.

Los permisos viven por la corrida y nunca llegan al disco — uno que sobreviviera a la sesión sobreviviría a la razón por la que alguien lo dio. Cada permiso, y cada llamada posterior que lo usó, quedan en el rastro: «¿por qué no me preguntó?» se responde después.

Limitar uma execução

sentineldesk-agent -run "instalá nginx y mostrame que anda" \
  -max-turns 40 -max-spend 0.50 -max-time 10m -mode ask

-max-turns es un punto de control, no un muro: al llegar se le pregunta al modelo si más pasos terminarían el trabajo, y detrás hay un techo duro que no puede negociar. -max-spend y -max-time son techos — terminan la corrida con lo que tenga, no la apuran.

Ler o que aconteceu

sentineldesk-agent -history          # todas las corridas, con turnos, llamadas y costo
sentineldesk-agent -history 42       # una corrida completa
sentineldesk-agent -export 42        # la sesión entera por stdout
sentineldesk-agent -costs            # cuánto se gastó, y en qué
sentineldesk-agent -resume 42        # retomarla; 0 es la más reciente

-history <id> muestra el plan del propio modelo al lado de lo que realmente hizo, nombra qué agente actuó cuando se delegó una subtarea, y dice claramente por qué se detuvo — blocked · over-budget, en vez de dejarte inferirlo de un contador de turnos que casualmente da el límite.

-resume redibuja la conversación y le dice al modelo cuánto hace que paró, y que el escritorio siguió corriendo sin él. Eso importa más de lo que suena: esto no es un agente de código retomando archivos que siguen donde los dejó — se cerraron ventanas, alguien más puede tener los controles, y la pantalla que recuerda es una fotografía.

Antes de gastar qualquer coisa

sentineldesk-agent -doctor                          # 15 chequeos contra el escritorio real, sin modelo
sentineldesk-agent -tools "auditar el firewall"     # qué se le ofrecería, y su ranking
sentineldesk-agent -skills                          # las skills encontradas, y de dónde salió cada una
sentineldesk-agent -providers                       # qué modelos se pueden alcanzar, y qué necesita cada uno

-doctor es lo primero que hay que correr cuando algo anda mal. Habla con el escritorio real, no involucra modelo y no cuesta nada. Si falla, el problema no es la clave.

Rodar no host

El agente encuentra solo el socket en el volumen sentineldesk-run, así que no tiene por qué estar en un contenedor:

docker compose up -d sentineldesk   # solo el escritorio
sentineldesk-agent -serve           # el agente, en el host

Es la forma más liviana de trabajar mientras cambiás el agente — no hay imagen que reconstruir entre ediciones. No corras los dos: dos runtimes en un escritorio significa que gana la conexión más nueva y la vieja se cae. No se rompe nada; solo confunde. Elegí uno.

O que vem instalado, e as duas imagens

De uma mesma construção saem duas variantes. Lite é a padrão; full acrescenta o que é grande demais ou específico demais para entregar a todo mundo.

Aqui «lite» não significa sem desktop — numa Raspberry Pi é exatamente isso que significa, mas aqui o desktop é o produto. Significa o conjunto mínimo que não deixa ninguém procurando um gerenciador de pacotes na primeira tarde: um navegador, um editor de texto, visualizadores de imagens e documentos, gerenciador de arquivos compactados, calculadora e monitor de processos, mais as ferramentas de rede para as quais este desktop costuma existir — nmap, dig, iperf3, tcpdump, mtr, sngrep e um cliente OpenVPN. Git também está lá, porque todo mundo clona alguma coisa.

Full soma LibreOffice, Firefox, GIMP, Wireshark, um ambiente de compilação e Go, e em máquinas Intel também Steam e Wine.

Go estar na full e não na lite é de propósito, mesmo este projeto sendo escrito em Go. Um toolchain são 250 MB para quem nunca vai digitar go, e «todo mundo clona alguma coisa» é uma afirmação que se sustenta para o git e não para um compilador.

Full contém lite

Full é construída sobre lite, e não ao lado, então tudo o que está numa está na outra. Além disso as duas compartilham quase todo o armazenamento: uma máquina que já tem lite baixa só a diferença.

Encontrar as coisas

O menu é agrupado pelo que você quer fazer. Terminal, Navegador, Arquivos e Editor de texto ficam no topo porque são o que se abre toda sessão; Acessórios, Rede e Ferramentas do sistema guardam o resto, e Todos os aplicativos lista tudo que está instalado.

As entradas de linha de comando dentro de Rede abrem um terminal com a sintaxe da ferramenta já impressa, para você não ter que ir procurar os parâmetros antes.

Conectar a uma VPN

Rede → VPN pede um perfil .ovpn e conecta. Os perfis guardados em ~/.openvpn são oferecidos diretamente, e a home sobrevive a reinícios: uma conexão configurada uma vez continua configurada.

Isso exige que o contêiner tenha sido iniciado com dispositivo de túnel e privilégios de rede. Se não tiver, a caixa de diálogo avisa e mostra as duas linhas que faltam, em vez de falhar em silêncio.

Relógio e teclado

Os dois são definidos quando o desktop inicia, então uma única imagem serve para qualquer região. O relógio segue TZ — qualquer nome padrão, por exemplo America/Argentina/Buenos_Aires — e o teclado segue KEYBOARD_LAYOUT: us, es para a Espanha, latam para a América Latina, e assim por diante.

Se algum estiver escrito errado, é avisado e ignorado em vez de ficar aplicado pela metade. Um relógio rodando em UTC em silêncio por causa de um erro de digitação é pior do que um que avisa.

Quando algo não funciona

Nada chega ao VLC

Quase sempre é uma de três coisas. Verifique nesta ordem:

  1. O VLC não está mesmo escutando. lsof -nP -iUDP:5000 tem que mostrar UDP *:5000. Uma porta alta aleatória significa que ele está chamando para fora, não escutando — faltou o @.
  2. O endereço aponta para um lugar que o contêiner não alcança. De dentro do Docker, localhost é o próprio contêiner, e um endereço do host que caia em 172.17.0.0/16 colide com a ponte do próprio Docker.
  3. Você está usando srt:// com o VLC. Veja acima.

A interface não mudou depois de recompilar

Deveria — o cliente é servido com um ETag sobre os próprios bytes, então o navegador é obrigado a revalidar. Se mesmo assim persistir, confirme que o contêiner foi recriado e não apenas reiniciado: make up reconstrói a imagem.

A imagem está mole, ou atrasada

Abra Estatísticas. Mostra o bitrate ao vivo, quadros, pacotes, o quanto você está atrás do ao vivo, e um relógio com milissegundos — que é a forma mais rápida de saber se dois navegadores estão realmente sincronizados.

A causa habitual é codificar 1080p por software. Defina ENCODER=x264 se a detecção automática caiu em VP8, e veja se o host tem uma GPU que valha a pena usar com nvenc ou vaapi.

As teclas não chegam à área de trabalho

Olhe o painel de presença: só o participante que tem o controle envia entrada. E se houver uma janela da camada de controle aberta, o teclado é dela, não da área de trabalho.
